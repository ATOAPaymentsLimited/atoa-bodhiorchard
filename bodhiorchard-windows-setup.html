Bodhiorchard — Native Windows Setup

Run the full stack on a Windows laptop without Docker. Config chosen: native PostgreSQL 16 + pgvector · Redis skipped · Ollama (local LLM) · manual PowerShell commands.
How to use this file: follow the sections top to bottom. Each command block has a Copy button. Run all PowerShell commands from the repository root (C:\path\to\atoa-bodhiorchard) unless a step says otherwise.

2Clone the repository

PowerShell
cd C:\dev
git clone git@github.com:ATOAPaymentsLimited/atoa-bodhiorchard.git

If you don't use SSH keys, clone over HTTPS instead: git clone https://github.com/ATOAPaymentsLimited/atoa-bodhiorchard.git. All later commands assume your current directory is this repo root.

3PostgreSQL 16 + pgvector

pgvector is required — the first database migration runs CREATE EXTENSION vector and will fail without it.

3a. Install PostgreSQL 16

Run the EDB installer. Accept defaults, set a postgres superuser password you'll remember, keep port 5432. You can skip Stack Builder at the end.

3b. Build & install pgvector

Must be the x64 prompt. Open "x64 Native Tools Command Prompt for VS 2022" from the Start menu — not the plain "Developer Command Prompt" (it defaults to 32-bit and the build fails with tupmacs.h ... case value '4' already used). Verify by typing cl alone: the banner must read for x64.
x64 Native Tools CMD
set "PGROOT=C:\Program Files\PostgreSQL\16"
cd %TEMP%
git clone --branch v0.8.0 https://github.com/pgvector/pgvector.git
cd pgvector
nmake /F Makefile.win
nmake /F Makefile.win install
If your PostgreSQL is installed elsewhere, change PGROOT accordingly. A prebuilt pgvector Windows binary for PG16 also works if you prefer not to compile — drop vector.dll into ...\PostgreSQL\16\lib and the vector* files into ...\PostgreSQL\16\share\extension.
If you already hit the 32-bit error: close the wrong prompt, open the x64 one, then clean and rebuild:
cd %TEMP%\pgvector && nmake /F Makefile.win clean && nmake /F Makefile.win && nmake /F Makefile.win install

3c. Create the database, user, and extensions

Open psql as the postgres superuser (SQL Shell (psql) from the Start menu, or the command below), and run the SQL block.

PowerShell
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres
psql (SQL)
CREATE USER bodhiorchard WITH PASSWORD 'bodhiorchard';
CREATE DATABASE bodhiorchard OWNER bodhiorchard;
\c bodhiorchard
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS pg_trgm;
\q
Enabling the extensions here (as the superuser) avoids a "must be superuser to CREATE EXTENSION" error when migrations run later.

4Ollama (local LLM)

After installing Ollama, pull the default model. Ollama serves on http://localhost:11434, which the backend uses automatically.

PowerShell
ollama pull llama3:8b
The llama3:70b premium model is optional and very large (~40 GB) — skip it unless you specifically configure it.

5Environment files

Create the .env files from the examples:

PowerShell
Copy-Item backend\.env.example backend\.env
Copy-Item frontend\.env.example frontend\.env

The defaults already point at local Postgres and Ollama, so minimal editing is needed. Open backend\.env and confirm / set:

  • DATABASE_URL = leave default (postgresql+asyncpg://bodhiorchard:bodhiorchard@localhost:5432/bodhiorchard).
  • LLM_PROVIDER=ollama and LLM_MODEL=llama3:8b (already the defaults).
  • REDIS_URL = leave as-is. Redis is skipped; the backend detects it's unavailable and falls back automatically. Background scan/PR-merge queueing is degraded — expected.
  • Set real secrets so encrypted-at-rest storage works:
    SECRET_KEY= any long random string
    ENCRYPTION_KEY= a Fernet key (generate it in step 6c).
frontend\.env default (VITE_API_BASE_URL=http://localhost:8000/api) needs no changes for local use.

6Backend — venv, dependencies, migrations

6a. Create the virtual environment

Build it with Python 3.12. Using py -3.12 guarantees the right interpreter even if a newer Python is also installed. The venv's Python must report 3.12.x — a 3.13/3.14 venv will fail dependency install.
PowerShell
py -3.12 -m venv backend\.venv
backend\.venv\Scripts\python --version
backend\.venv\Scripts\python -m pip install --upgrade pip
The second line must print Python 3.12.x. If py -3.12 isn't found, use the full path, e.g. "C:\Users\Admin\AppData\Local\Programs\Python\Python312\python.exe" -m venv backend\.venv. Already made a 3.13/3.14 venv? Delete it first: rmdir /s /q backend\.venv.

6b. Install dependencies

Use the requirements file (matches "pip install requirement"):

PowerShell
backend\.venv\Scripts\pip install -r backend\requirements.txt
Alternative (also installs dev tools — ruff, mypy, pytest): backend\.venv\Scripts\pip install -e ".\backend[dev]". Either works for running the app.

6c. Generate the encryption key

PowerShell
backend\.venv\Scripts\python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

Copy the output into backend\.env as ENCRYPTION_KEY=....

6d. Run database migrations

PowerShell
cd backend
.\.venv\Scripts\alembic upgrade head
cd ..
This creates all tables and the HNSW vector indexes. If it errors on the vector extension, revisit step 3b/3c.

8Start the service

The bundled start script is bash-only, so start each of the three processes in its own PowerShell window. Make sure Ollama and PostgreSQL are running first (both install as auto-start services).

Terminal 1 — Backend (port 8000)

On Windows, do NOT start with uvicorn --reload. Under --reload the app's Windows event-loop fix runs too late, leaving a SelectorEventLoop that cannot spawn subprocesses — so git clones, repo scans, and the AI-agent connection test crash with NotImplementedError (the setup wizard shows "Server unreachable"). Use the launcher below, which sets the Proactor policy before uvicorn creates its loop.

Create backend\run_win.py once with this content:

backend\run_win.py
import asyncio
import sys

if sys.platform == "win32":
    asyncio.set_event_loop_policy(asyncio.WindowsProactorEventLoopPolicy())

import uvicorn

if __name__ == "__main__":
    uvicorn.run("app.main:app", host="127.0.0.1", port=8000, reload=False)

Then start the backend with it:

PowerShell
cd backend
.\.venv\Scripts\python run_win.py
Trade-off: no hot-reload — restart this window after backend code changes. Everything else (subprocess spawning, agent runs, scans) now works.

Terminal 2 — Frontend (port 3000)

PowerShell
npm run dev:frontend

Terminal 3 — Multiplayer (port 2567)

PowerShell
npm run dev:multiplayer
Then open http://localhost:3000 in your browser.

Common issues

SymptomFix
pgvector build fails: tupmacs.h ... case value '4' already used You're in a 32-bit prompt. Use the x64 Native Tools Command Prompt for VS 2022 (verify cl says for x64), then nmake /F Makefile.win clean and rebuild. See step 3b.
Migration fails: extension "vector" is not available pgvector isn't installed into this Postgres. Redo step 3b (correct PGROOT, x64 prompt), then 3c.
Log shows redis_unavailable_using_fallback Expected — Redis is intentionally skipped. Not an error.
Setup wizard "Server unreachable" on the AI Engine test; backend log shows NotImplementedError at create_subprocess_exec Backend is on a Windows SelectorEventLoop. Start it via backend\run_win.py (not uvicorn --reload). See step 8, Terminal 1.
AI Engine step: Ollama shows "Soon" / only Claude, Copilot, Codex selectable Expected — the coding agent can't be local yet. Use a Claude/Copilot/Codex account. Local Ollama still powers embeddings/synthesis.
Backend can't reach the LLM / agent calls hang Ensure Ollama is running and ollama pull llama3:8b completed.
pip install fails: Could not find a version that satisfies... / no matching distribution, wheels named cp313/cp314 Your venv is Python 3.13/3.14. This project needs 3.12. Delete the venv (rmdir /s /q backend\.venv) and recreate with py -3.12 -m venv backend\.venv. See step 6a.
pip install fails building a package Install the Visual C++ Build Tools ("Desktop development with C++") and retry.
Frontend loads but API calls 404 / fail Confirm the backend is running on 8000 and VITE_API_BASE_URL in frontend\.env is http://localhost:8000/api.
Port already in use Find the process: netstat -ano | findstr :8000, then taskkill /PID <pid> /F.
Optional — add Redis later. If you want the full background scan / PR-merge job queue, install Memurai (a native Redis-compatible Windows service) and leave REDIS_URL=redis://localhost:6379. No code changes needed.
